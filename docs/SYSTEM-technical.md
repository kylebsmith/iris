# iris: a single-header C99 library for interactive supervised learning on embedded hardware

**Version 0.1.0.** BSD 3-Clause, `Copyright (c) 2026, Kyle Smith`. One header, no build system: `cc -std=c99 -O2 -I. -o hello examples/01_hello.c -lm`.

*(This document deliberately does not restate the header's line count. It was wrong here by 750 lines for a fortnight, because it was a second copy of a number nothing compared against reality. The count lives in `README.md`, where `build.sh claims` fails the build if it drifts. One number, one place, one check.)*

## 1. System

iris is a supervised-learning runtime for the Wekinator interaction loop — demonstrate gesture/parameter pairs, train, play — sized for a microcontroller. `struct iris` is 248 bytes; everything else lives in a caller-supplied arena whose size is computed by a macro. `IRIS_ARENA(2,12,3,256)` is 9,264 bytes and equals `iris_size()` exactly (audit: "macro 9264 B, needed 9264 B, slack 0 B"). Zero allocator calls were observed across record-40 / train-800-epochs / 100,000 predictions / delete-and-retrain, via `DYLD_INSERT_LIBRARIES` interposition over the malloc family — macOS/dyld only. Hard limits: 32 inputs, 16 outputs, 4,096 examples ("to stop an overflow, not because 4096 is musically special"), 64 hidden units.

Determinism is enforced in three layers: an `#error` tripwire that refuses to compile under `__FAST_MATH__`; `#pragma STDC FP_CONTRACT OFF`; and golden FNV-1a blob hashes asserted as live tests. The pragma is honoured by clang except under `-ffp-contract=fast`, and ignored by GCC (including xtensa-esp32s3) always — those builds must pass `-ffp-contract=off`. A sweep of `{-O0,-O1,-O2,-O3,-Os} × {default, off, on, fast}` on Apple clang 17/arm64 passes both golden checks in 16 of 20 combinations; the four failures are all `-ffp-contract=fast`, at `-O1/-O2/-O3/-Os` — `-O0 -ffp-contract=fast` passes. The blobs reproduce bit-exactly on x86_64 under Rosetta and on GCC 15/arm64 with `-ffp-contract=off`. The ESP32-S3 determinism leg is untested: no on-device blob check exists.

## 2. Model

One hidden layer, not configurable — `iris_init` takes a width and no depth argument. `hidden_h = tanh(Σ w1[h][i]·x_i + b1[h])`, `out_o = sigmoid(Σ w2[o][h]·hidden_h + b2[o])`, one hidden vector shared by all outputs. Inputs are min-max normalised to `[-1,+1]` (format v3; v1/v2 instruments keep `[0,1]` per-instrument, read from the file version word), outputs to `[0.1, 0.9]` because a sigmoid only approaches its asymptotes. Outputs are de-normalised and then hard-clamped, with no opt-out, to the ranges **last fitted** by `iris_fit_ranges` — which is the demonstrated range only until a delete or a clear makes those ranges stale, and until the next fit refreshes them. `iris_reseed` draws `w1 ~ U[-1,1)/√n_in`, `w2 ~ U[-1,1)/√n_hid`, biases exactly 0, from xorshift32.

`tanh` is a Padé rational, `x(27+x²)/(27+9x²)`, clamped at |x| > 4.9. Its maximum absolute error is **0.0283 at x = 4.9** — the header's former "about 0.001" holds only for |x| < 0.31. Because `f(x) − 1 = (x−3)³/(27+9x²)`, it leaves tanh's codomain for `3 < |x| ≤ 4.9`, peaking at 1.02822, so both backprop factors change sign in that band: the hidden factor `(1−a²)` in `d_hid` goes negative, bounded at **−0.0572** at |s| = 4.9 where the true derivative is +0.000222, and `d_out`'s `y(1−y)` goes negative once `iris_sigmoid` passes y = 1.0141. This band is entered on 0 of 192,000 hidden pre-activations on the fixed-epoch path, and on 40 of 40 seeds (2.5–4.2% of hidden evaluations) under the converging trainer. Both proposed repairs measured worse over 100 seeds: shipped recall/grid 0.001522/0.009995; derivative clamped ≥0, 0.001591/0.009998; exact Padé derivative, 0.002011/0.010584. Against libm `tanhf` over 40 paired seeds, grid error is 0.0100403 vs 0.0100383 (t = 0.06; 21 of 40 favour the Padé). The measured speed margin is ~2×, not the 30× once claimed.

## 3. Trainers

The update rule exists once, in `iris_internal_train_run`: `v = momentum·v − lr·g·x; w += v`, biases with the input factor omitted; `d_out = (y−t)·y·(1−y)`, `d_hid = (Σ w2·d_out)(1−a²)`. Defaults lr 0.10, momentum 0.85, clamped to [0.0001, 2.0] and [0.0, 0.99]. Updates are per example; `order[]` is Fisher–Yates shuffled at the top of every epoch from the persistent instrument RNG (which is why RNG state entered the file format).

- **`iris_train_epochs`** — fixed-epoch backprop, the reference implementation, bit-pinned by audit check 12.
- **`iris_train_converge`** (recommended) — plateau test every `IRIS_CONV_WINDOW 2000` epochs, stop when a window buys < 10% of the error, ceiling 60,000. Three further rules can end a run: an unconditional `err < 1e-6f` floor that sits *outside* the convergence guard, a divergence clamp at |w| > 16, and a callback returning 0. The floor dominates in practice: at 5 examples, 36–39 of 40 seeds stop there. `examples/01_hello.c` stops at 2,557 epochs, error 9.98e-07 — not a multiple of 2,000, so it stopped on the floor, and the plateau test cannot structurally fire before epoch 4,000.
- **ELM** (`iris_train_elm*`, in-header) — frozen random hidden layer at gain 2/√n_in, output layer solved as ridge least-squares *in logit space* by one (nh+1)² Cholesky. Ridge is mandatory and relative (`lam0·trace/K + 1e-7`), with up to **8 deterministic λ-doublings** on failed factorisation. Refuses nh < 8. 90 hostile solves: 0 unfixable, max 2 escalations. At nh=48 its fit floor beats backprop (recall 0.0030 vs 0.0059).
- **L-BFGS** (m=5, Armijo c1=1e-4) — moved to `experimental/iris_lbfgs.h`, 358 lines, **zero production callers**; all nine call sites are in `tests/audit.c`. Its device promotion was gated on two ESP32-S3 measurements never taken.
- **`iris_knn_predict`** and **`iris_classify_1nn`** — inverse-squared-distance regression (k settable, clamped to 8) and a bit-verbatim 1-NN snap at fixed k=1, both training-free.

## 4. Relation to Wekinator / Weka 3.6.12

Wekinator never calls `setLearningRate`, `setMomentum`, `setTrainingTime` or `setOptions`, so Weka's constructor defaults stand: lr 0.3, momentum 0.2, 500 epochs.

**Structurally faithful** (checkable by inspection, not by comparing outputs): the per-weight recursion **within a run** is an exact rewrite of Weka's `delta = lr·err·x + momentum·delta_prev` under the opposite sign convention — different activations, defaults and shuffle still make the trajectories differ; per-sample granularity (`n_ex` writes per epoch, not one) — scope: `iris_train_epochs` only; one fully-connected hidden layer; the bias placement and update; and `iris_classify_1nn`, which reproduces Wekinator's default `KNNModelBuilder` at k=1 with min-max squared Euclidean and earliest-recorded tie-breaking. That last is checked at 441 probes with 441 agreeing, 0 disagreeing and 0 distance ties — but **against an independent double-precision reference we wrote to Weka IBk + LinearNNSearch semantics, on a deliberately separate code path; the Java has never been run**, and the agreement cannot be bit-exact in principle (float32 accumulation can reorder near-ties against Weka's double, and our 1e-6 zero-range floor differs from Weka's treatment of a constant attribute). The clamps admit Weka's pair, so `iris_set_learning(k, 0.3f, 0.2f)` is reachable.

**Deliberate divergence.** Ours: sigmoid outputs, always clamped; theirs: `setEndsToLinear()`, clamped only on request (`LimitType.HARD`; default `SOFT`). Bounded saturating output matched to the demonstrated range is a tradeoff, not a win — for a filter cutoff on hardware, unbounded extrapolation is a fault; for a musician reaching past their demos, our clamp is a wall. Ours: Padé tanh; theirs: double-precision logistic. Ours: one net with a shared hidden vector; theirs: one `MultilayerPerceptron` per output — **which way the fit goes is unmeasured**. Ours: no depth knob; theirs: a 0–3 combo box — a removed affordance with a measured cost (`discont2d` generalises 15× worse than `smooth2d`; nothing measures a two-hidden-layer iris). Ours: lr 0.10 / momentum 0.85 — **unargued**, with no ADR or ablation in the tree comparing 0.85 against 0.2. Ours: reshuffle every epoch; theirs: once — theirs has the stronger rebuild reproducibility (1×600 vs 3×200 epochs gives max|Δw| 0.0099 here). Biases 0.0 vs U(−0.05, 0.05). And **binary32 against binary64 throughout, which makes numerical identity impossible in principle**; it buys 1.75× less arena.

Wekinator has nine algorithm families; iris implements the MLP and 1-NN. The largest hole is FastDTW — 6,662 lines there, zero temporal machinery here (`iris_predict` is a pure function of the current frame). `LinearRegression` is the hardest omission to defend: it is index 1 of the *numeric* registry, inside the mode we reconstruct. Also absent: cross-validation, per-output input subsetting, user-settable k **on the classification path** (`iris_classify_1nn` is fixed at k=1 where Wekinator's `KNNEditorPanel` exposes it; `iris_knn_predict` does take a k, capped at 8), and the 22-verb OSC control plane.

## 5. Residual ledger

The original contribution is `iris_example_stress` / `iris_worst_example`: an integrated per-example residual accumulated during training, exposed as a ranking of which demonstration fights the others. Wekinator's nearest equivalent is a per-*model* number (`ModelEvaluator.pctCorrect()`); nothing there scores an individual example. Detection of one corrupted demo among twenty (nh=12, 8 outputs, 20 trials): integrated residual **6/20, 18/20, 17/20, 17/20** at corruption +0.05/+0.10/+0.20/+0.40, against final-residual 8/5/2/2 and leave-one-out CV 1/1/10/11. It is a *margin* (`IRIS_STRESS_FLAG 2.5`), not a level, because worst-of-n on clean data reaches 1.76 at 5 examples and 9.23 at 100; it is silent below 12 examples. Live: corrupted demo ranked first in 11 of 12 audit trials. `examples/02_fix_a_mistake.c` flags id 15 at margin 3.42.

## 6. Measured cost, with scope

The audit prints 40 `PASS` lines, `ALL CHECKS PASSED (0 failed)` (README's "35" and build.sh's "twenty-five" are stale).

**On device, once, ever:** 600-epoch backprop on an ESP32-S3, **321.0 ms at 20 examples and 3,204.6 ms at 200** — 16.03 ms per example per 600 epochs (`BRINGUP-LOG.md:198`). Scope travels with it: measured 2026-08-21 on the **embwek v0.1 core**, Arduino esp32 3.3.3 default flags (`-Os`, where the host builds at `-O2`), one board, one unit — it is not a measurement of 0.4.0. Everything else labelled S3 is host × 270; the scaling was ×32 in 0.3.0 and was corrected in 0.4.0 against that one measurement. On that scaling: one prediction is 0.027–0.029 µs host, ~7.4–7.8 µs S3, or 0.74–0.78% of one core at 1,000 gestures/sec. `iris_train_converge` at 20 examples spends 16,000 epochs, 25.1–26.2 ms host, ~7 s scaled — **unmeasured on device**. ELM at nh=12, 20 examples: 0.0028 ms host. Separately, a live interface measured gesture→MIDI p50 0.92–1.24 ms, worst frame 2.42 ms, against a 10 ms bar — one board, one unit, with a ~100 Hz touch scan upstream and a ≤1 ms USB frame downstream, so realistic finger-to-host mean is ≈6 ms.

Fit quality (8-output synthetic reference, 20 examples, nh=12, 9 seeds): 600 epochs → recall 0.0112 / grid 0.0158; 60,000 → 0.0012 / 0.0083. Recall improves 5.9×, held-out grid 1.8×, and the curve reverses — at 50 examples a fixed 200,000-epoch budget generalises *worse* than 60,000 (0.0065 vs 0.0063).

## 7. Limitations

These are load-bearing, not caveats.

1. **No head-to-head measurement exists in the harness.** `benchmark/results/{wekinator,rapidlib,memlp}.json` are all `"status": "stub"`. Every accuracy and speed figure above is intra-project or against a reference we wrote. One off-harness feasibility probe exists and must not be published as a result: its 0.0135 spread across implementations is ~2.4× iris's own 8-seed spread, at one task and one seed per arm.
2. **The recommended trainer is provisional.** Every figure supporting it was measured on smooth noiseless synthetic targets. A 16-seed re-run with additive sensor noise inverts the ranking: at σ=0.05, plateau-stopped SGD gives grid RMSE 0.08513 against 0.02845 for a fixed 100-epoch ceiling; at σ=0.10, 0.15002 against 0.05009. Real sensors are noisy. `docs/adr/0021` carries a ⚠️ PROVISIONAL banner and names its own blocking experiment.
3. **Only one on-device training measurement exists** (§6), and nothing about `iris_train_converge` has been measured on hardware.
4. **Nothing is verified on recorded human gesture** — not accuracy, not the plateau criterion, not the ledger's premise. Every benchmark task is 441 static probe points; the one gesture-shaped loader's header reads "NO HUMAN RECORDINGS EXIST YET".
5. The plateau criterion measures fit, not generalisation; the repository's own strongest counter-measurement is a 1.93× regression on a locally-structured target at 20 examples, 2.7× outside the shipped reroll band.
6. The Padé defect (§2) is knowingly carried. The ELM's 2/√n_in gain has no reproducible measurement behind it — the header retracts its own former citation. The save format carries no algorithm tag, so a file cannot say which trainer produced it. The ledger does not find small errors (6/20 at +0.05), and its 12-example floor comes from the same table that validates it. `iris_correct` and `iris_migrate_scaling` have no production callers. Delete-and-re-record does not return the instrument you would have had (non-identical in 32/32 replicates, median deviation 0.0021 of range) because the shuffle is by position. "Zero undefined symbols" is false as literally stated: a default macOS clang invocation injects `___stack_chk_fail` and `___stack_chk_guard`; the claim holds only with `-fno-stack-protector`, and xtensa-gcc is unverified.
